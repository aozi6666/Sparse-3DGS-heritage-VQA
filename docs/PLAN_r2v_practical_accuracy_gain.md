## 4. 推荐执行路线：先简单、再增加视觉信息，最后才考虑复杂验证

### 路线 A：同视图的选项均衡换序与语义投票（第一优先）

- 直接复用现有 Mage 推理环境和视频路径输入接口，不需要额外大模型或训练。
- 固定四种排列：原顺序及三种循环移位，使每个语义选项分别出现于 A/B/C/D 一次。
- 四个排列不覆盖全部 24 种排列；先不扩展到 24 次全排列或大量随机采样。
- 每次将输出字母和四字母分布逆映射到稳定的原选项 ID；不得直接对新字母投票。
- 主聚合器提前固定为语义多数票；平票优先原始顺序的答案。若原答案不在平票候选中，用逆映射后的平均字母概率在平票候选内决胜，仍相同则按原选项 ID 固定顺序处理。
- 一个预先登记的对照聚合器：同视图四次逆映射后的概率均值。不得在测试集上临时更换聚合器。
- 无法解析的 ballot 明确记录并计入非法率；不能强制把非字母词表 argmax 悄悄替换成合法字母。全部 ballot 无效时按约定回退原答案，并保留非法标记。
- 检查“以上全部”“A 和 B 都对”等依赖选项位置/标签的文字：不能无损重排时保留原输入、回退并记录原因；题目不从主分母删除。
- 先重点验证 Frames-32 的投票，再用同协议 Codec-32 投票作控制。单路投票有增益时，优先选更简单的单路系统，不强制加入跨视图 Gate2。
- 可保留一个固定的双视图语义融合对照，但不继续搜索跨路径权重或 margin 阈值。

### 路线 B：增加有效视觉覆盖（A 无收益或收益有限时的低复杂度备选）

- 在独立新配置中测试 Frames-48，再按预设条件决定是否测试 Frames-64；`max_pixels=150000`、`min_pixels=3136` 起步不变。
- 每次先 5–6 题检查显存/时延，不自动升帧数；OOM 立即停，不自动量化/换环境/改低预算。
- 这是增加计算的增强配置，**不再冒充原阶段 1 的 Frames-32 同协议配对**。
- 必须与原 Codec-32、原 Frames-32 同时报告准确率及成本，不裁剪/削弱 Codec 作为对照。
- “更多帧单次推理”和“相同帧数多次换序”分别比较实际 token/耗时，不能仅凭调用数假定成本相同。
- 新帧数若带来稳定增益，再考虑是否和四排列投票组合；不直接枚举所有帧数、像素、提示词的组合。

### 路线 C：受限证据验证（默认后置、不是必做）

- 仅当 A/B 都没有足够收益而仍决定继续时，再单独评审是否投入，不能把所有备用方法一次堆上去。
- 借鉴 VideoHV 的思路，让候选在相同证据输入上比较，并加等预算随机片段对照；同一模型声称“verified”不等于真实证据。
- 使用 Mage 本地串行调用，不照搬外部 API/新模型依赖；不直接做多 Agent 系统或训练网络。
- 如需 A.I.R. 风格检索，先检查本地既有 CLIP 权重和依赖是否完整；未满足时报告缺项，不自行下载。
- VCD/视觉对照只作为可选小实验，不照搬图像加噪后承诺视频涨点。

## 8. 断点续跑、tqdm 与防断线要求

- “断点”首先指计算断点续跑，不等于 SSH 连接永远不断，也不是文件传输协议。
- 最小保存单元拟为 `(index, backend, visual_config, permutation_id, operation)`；完成一个单元就追加 JSONL、flush、fsync。
- 断点 key 包含配置签名/模型与脚本身份；改变 Prompt、帧数、像素、聚合规则、token 处理或数据清单时开新标签，不能混跑。
- 同目录文件锁拒绝并发写；按完整记录恢复已完成单元，不仅按整题粗略跳过。
- 输出残缺尾行、重复 key、字段冲突或哈希漂移时停止并保留，不静默修复。若出现仅配置锁尾写不完整，也不得覆盖。
- 每题的最终聚合必须等待其必要单元齐全；原始单元、最终预测、离线统计分别可追溯。
- tqdm 显示总题数、已完成题数、当前 backend/permutation、单元进度、速度和 ETA；续跑时恢复 initial。
- Ctrl+C 停止后不留隐形 GPU 子进程；未落盘的当前单元允许重跑。
- 先检查服务器是否已有 tmux；有则提供可重连的 tmux 命令。没有则提供前台命令和断点恢复说明，不擅自安装，也不声称断线后任务一定继续。
- 后续 `.sh` 明确区分 preflight / smoke / dev / val / test / full / summarize；一条命令只启动一个阶段，不从冒烟自动跑到全量。
