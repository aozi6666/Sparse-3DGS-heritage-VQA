## 1. 使用范围与核心判断

本计划把发表版 SynGS 的已有成果、服务器当前工程实验、后续拟补实验分开记录，供硕士论文写作和后续实验实施追溯。它不要求重跑全部发表版基线，也不以增加图表数量作为完成目标。

优先补齐四类证据：

1. 深度增强与 Drop 的独立作用及相互作用。
2. 相对 GaussianObject 直接基础方法的改进，并区分粗重建与扩散精化。
3. 几何增强与修复阶段的真实过程资产。
4. 小幅收益的重复稳定性，以及改进对应的时间、显存和模型规模代价。

当前用户确认的研究边界：

- SynGS 的 Visual Hull、VGGT 引导补点、训练 Drop 是第三章必须保留的主要方法内容。
- Visual Hull 的既有实现、GaussianObject 的扩散修复、ControlNet 与 LoRA 应说明来源。原始模块不是本文首次提出；应准确描述本文的组合、改进与验证。
- 服务器新增的 depth_head 任务适配、CADR、底模切换不自动等同于发表版 SynGS 创新。收益有限或为负的结果保留，不提升为核心贡献。
- 三维重建与原始视频 VLM 问答是两项独立工作。视频问答没有使用重建新视角或三维信息。
- 文物数据集由用户后续选择，目前未选定、未下载、未完成文物场景实验。
- `docs/thesis.md` 是历史总体设计稿，其中三维资产与视频问答空间融合的设想不作为当前已完成事实。本轮不改该历史文件。

## 4. 当前工程结果与可解释边界

### 4.1 kitchen 粗重建组合

当前归档协议主要为：9 个训练视图、4 视图生成的初始化、分辨率因子 4、SH=2、粗训 10k、test 集。

| 初始化 | 不使用 Drop 的 PSNR | 使用 Drop 的 PSNR |
|---|---:|---:|
| 原始 Visual Hull | 27.111653 | 27.103455 |
| VGGT 增强 | 26.046313 | 26.141084 |

在此设置下，VGGT 增强的 PSNR 比原始 Visual Hull 低；Drop 的 PSNR 作用较小。不同指标可能呈不同变化，不能只按 PSNR 概括全部画质。

点云统计：原始 Visual Hull 为 8616 点，增强版本为 2874 点；增强版本包围范围更大。点数减少与空间扩散是需要核查的现象，尚不能仅凭此确定因果。

### 4.2 场景与任务适配差异

| 场景，均开启 Drop | 原始 Visual Hull | 原 VGGT 增强 | depthft |

| garden | 33.485916 | 33.373816 | 33.530326 |

depthft 当前表现有场景差异，且现有多场景适配不是 hold-out。它不能直接支撑「普遍改善」「跨场景泛化」结论。

### 4.4 扩散修复结果

| 初始化，均开启 Drop | 粗训 PSNR | RV51 修复后 PSNR | 差值约值 |
|---|---:|---:|---:|
| 原始 Visual Hull | 27.103455 | 27.084541 | -0.018915 |
| 原 VGGT 增强 | 26.141084 | 26.966551 | +0.825467 |
| depthft | 25.978 | 27.021628 | +1.044 |

## 7. E01：GaussianObject 直接基线

**问题：** 核心改进相对直接基础方法带来什么？最终提升是否主要来自已有扩散修复？

| 层次 | 比较配置 | 固定条件 |
|---|---|---|
| 粗重建 | GaussianObject coarse、coarse+Drop、SynGS core | 同训练视图、背景、掩膜、分辨率、基础优化条件与预算 |
| 完整流程 | GaussianObject full、SynGS core+相同类别repair | 同输入权限、修复预算、底模与LoRA训练条件 |

- 原始3DGS、DropGaussian及发表版强基线保留；不默认新增一长串方法。
- 当前「原始Visual Hull、不Drop」只能作为GaussianObject coarse候选，核对漂浮点清理、损失和调度后再确定名称。
- 粗训比较与完整流程比较分别成表。不同方法按其公开推荐设置复现时，应披露训练代价；核心模块消融则严格控制非目标变量。
- 所有基线实际使用的掩膜、深度、相机、SfM点云权限要记录，避免输入不等价。
- 新增表输出逐场景和平均 PSNR／SSIM／LPIPS，附训练时间。发表版表无需因本计划而全部重跑。
- GaussianObject 的 Visual Hull、漂浮点消除、leave-one-out样本生成、扩散修复注明引用。

对应章节：3.7.3、3.7.5。

## 8. E02：几何增强 × Drop 核心组合消融

**问题：** 几何增强与训练正则化是否独立有效，是否相互补充？

| 运行后缀 | Visual Hull | 深度增强 | Drop | 扩散修复 |
|---|---|---|---|---|
| a_hull | ✓ | — | — | — |
| b_hull_depth | ✓ | ✓ | — | — |
| c_hull_drop | ✓ | — | ✓ | — |
| d_hull_depth_drop | ✓ | ✓ | ✓ | — |

主要对照：B−A、C−A、D−B、D−C；交互项可写为 `(D−B)−(C−A)`。只在同场景、同视图、同种子、同评测协议内计算。

建议主设置：4个训练视图、事先固定至少3个代表场景。可先核查 kitchen／bonsai／garden 的可用性并冻结选择；现有9视图结果作为扩展，不能当成已完成4视图。

控制变量：

- 同一场景A/C共用同一份原始初始化，B/D共用同一份增强初始化。
- 模型训练迭代、稠密化、漂浮点处理、损失、分辨率、掩膜和种子一致。
- 初始化应来自协议允许的训练图像；4视图主设置不默认引入更多辅助图像。
- 主消融先关闭repair，后者独立在E06评估。

产物：四组逐场景表、场景平均、至少两个相同测试视角的局部细节与误差图，补点与最终高斯数量。不要仅靠一个最优场景说明有效性。

首轮3场景×4配置=12个粗训配置；这是配置数，不是GPU时长估算。E01/E03可复用等价配置；E07的重复只增加选定关键组，不重复全部方法。

Visual Hull作用可结合原始3DGS初始化参照。不要求无意义的全八组合；未度量对齐的纯VGGT点云失败不能单独作为必要性证明。

对应章节：3.7.4。

## 9. E03：几何增强与可靠性筛选机制

**问题：** 新增点在哪里，筛选移除了什么错误，融合后结构是否改善？

| 配置 | 内容 | 对照目标 |
|---|---|---|
| G0 | 仅Visual Hull | 初始化基础 |
| G1 | 允许区域内直接深度补点，关闭目标可靠性筛选 | 直接引入预测深度的影响 |
| G2 | 同样补点流程，开启可靠性筛选 | 门控与可靠区域筛选 |
| G3 | G2基础上使用任务适配深度 | 适配的额外收益，是否纳入由E05决定 |

固定深度尺度处理、坐标系、候选点生成规则、融合参数、预算与后续优化。关闭筛选时仍保留有限值、正深度和图像边界等必要合法性检查，不能故意生成非法输入。

每组保存：

- 输入RGB、前景轮廓、预测深度、真实使用的可靠区域／门控标记。
- 原Visual Hull点、候选新增点、保留新增点、融合后点云，颜色区分来源。
- 候选／保留／最终点数、保留比例、AABB和稳健空间范围、跳过增强的视图或场景比例。
- 同一坐标系与观察相机下的点云，及训练后同一测试帧。
- 若模块因阈值回退到纯Visual Hull，明确标记，不把回退结果称为补点成功。

当前 kitchen 点数与包围范围异常先作实现核查。需要区分是否因为重建网格、尺度、裁剪范围或融合方式不同；在原因未明确前不预设「点数越多越好」。

可选增加相近点数的初始化对照，用于分离数量与位置质量。若缺真值几何，重投影与可视化是代理证据，不等同真实几何精度。声称几何精度时另需真实扫描或模型参考及统一对齐、采样协议。

对应章节：3.3、3.4、3.7.4。

## 10. E04：Drop泛化与机制验证

**问题：** Drop是否缓解训练视图过拟合，是否改善弱观测区域？

- 固定同一份初始化，比较无Drop／采用的Drop。
- 随训练记录训练集与测试集PSNR，必要时附SSIM／LPIPS。
- 评估时统一完整高斯渲染、固定背景，关闭训练随机丢弃；训练损失与完整渲染指标分列。
- 保存对应步数的同一测试视角，观察浮点伪影、细结构与遮挡边界。
- 记录真实高斯数量，防止训练容量差异未被解释。

如最终方法采用本地现稿的双分支DVR，则增加「补偿DropGaussian／去补偿Drop／双分支DVR」针对性对照，固定初始化和其余设置。若实际采用补偿DropGaussian，应准确说明继承和作用，不强行写成双分支新方法。

若保留「梯度重分配」主张，需要补原始统计并固定：

- 梯度变量，如屏幕空间位置梯度，及范数定义。
- 可见／不可见、保留／被Drop点的计入规则与样本数。
- 距离归一化、区间、相机集合、训练时间区间。
- 跨迭代与随机种子的汇总方式。

距离远不等于可见性弱；梯度变大也不自动等于图像质量更好。要与测试画质和区域变化共同解释。已有 `gradient.pdf` 在原始统计找回前仅登记为待核查资产，不描点当作新实测。

参数敏感性放到E09，先完成泛化对照。

对应章节：3.5、3.7.4。

## 11. E05：深度任务适配的条件验证

**纳入条件：** 若3.4.1要主张任务适配改善重建，则此项必须；若只作为工程探索，则保留现有结果并收敛表述。

对照原始VGGT权重与适配权重，使用相同合法输入、可靠性筛选、坐标尺度、初始化融合和后续GS训练。

两种任务定位须单独说明：

1. 场景内适配：只用该场景协议允许的训练视图与监督，适配成本计入每场景流程。
2. 跨场景适配：适配场景与评测场景隔离，冻结权重后评测未见场景；验证集用于选超参数。

当前全视角、评测场景内的depthft保留为开发性历史结果。不能通过重新命名把它变成hold-out结果。

深度误差评价如使用稀疏SfM参考，应说明其来源；若同一参考既用于微调又用于误差评价，不称为独立测试。尺度对齐参数应由允许的训练／校准数据得到，不利用测试真值为重建提供额外信息。

产物：适配数据清单、可训练参数范围、权重哈希、独立深度评价（具备条件时）、初始化变化、最终新视角指标与适配成本。

对应章节：3.4.1、3.7.4；收益有限时作为扩展说明。

## 12. E06：扩散修复扩展实验

**问题：** 修复对不同粗模型的收益、代价和适用条件是什么？

基础矩阵：原始Visual Hull／VGGT增强／任务适配增强三种粗模型，各自比较修复关闭与开启。任务适配不纳入最终方法时可只保留前两种。

repair前后始终从同一粗模型出发。底模、预算、相机采样、随机种子和评测帧固定。初期选择一套固定修复配置，不继续穷举SD底模。

明确两种实验：

- **共用修复模型：** 固定同一个LoRA，观察不同粗模型接入后的表现，回答迁移适用性。
- **完整流程公平比较：** 各方法按匹配预算构建自身修复样本、训练LoRA，再比较最终模型；回答完整方法性能。

现有复用VGGT路线LoRA的结果属于前一种，不能无说明地代替后一种。

过程图保存同一目标相机的：受损渲染、修复模型输出、精化后的最终GS渲染、GT（若有）。修复样本中的参考图与用于评测的GT严格区分；测试GT不能作为修复输入。

至少增加1—2个事先固定场景验证场景依赖；当前kitchen结果先保留。记录PSNR、SSIM、LPIPS和额外耗时。CADR与底模既有对照可整理为紧凑扩展表，不作为新主贡献。

对应章节：3.6、3.7.5。

## 13. E07：稳定性与重复实验

选择两个固定代表场景、关键成对配置，建议至少三个随机种子。示例0／1／2仅为计划，实际运行前冻结。

- 固定视图清单，先测训练随机性。若研究视图选择随机性，则另设实验，不混为一种方差。
- 同种子成对比较，记录每次绝对值与差值，报告均值、样本标准差和运行次数。
- 每个场景先汇总种子，数据集平均采用统一场景权重。多个测试视图不是多次独立训练。
- 约0.04—0.15 dB的小变化结合方差解释，不预先认定有效或无效。
- 三次重复主要用于描述波动，不自动声称统计显著性。
- 保留预先选择的全部场景与种子，包含负结果，不用测试集选阈值或只挑涨点运行。

对应章节：3.7.4、3.7.5。

## 15. E09：鲁棒性与敏感性，第二优先级

### 15.1 深度扰动

适用于最终确实保留可靠性筛选的版本。固定两个代表场景，比较筛选开／关，在干净深度和少量预定义扰动下的表现。

可选一种主扰动：深度相对噪声，或局部深度缺失。噪声幅度、有效像素、尺度单位、随机种子和缺失位置生成方式必须写清，不直接照搬其他论文的「10%噪声」而不定义。

记录最终画质、候选／保留点数、跳过增强比例。指标不变可能因为模块回退到Visual Hull，需结合实际启用情况解释，不能据此直接宣称鲁棒。

### 15.2 少量参数分析

- Drop：默认值附近两侧各一档，保持其他设置固定。
- 可靠性阈值：选少量有实际意义的阈值，记录启用率和补点量。
- 比较固定与渐增Drop日程时，同时披露平均丢弃率与最大率；避免把丢弃总量变化混作调度贡献。
- 参数在验证集确定，冻结后报告测试结果。

不同时开展深度、掩膜、位姿、底模四类大范围扫描。

对应章节：3.7.4，或正文末尾简短扩展分析。

## 17. E10：用户自选文物数据集的实施条件

可以由用户选择。建议公共基准承担方法比较，文物对象承担场景适用性验证；二者独立成表、分别说明结论范围。新增文物案例不直接继承发表表格中的指标。

### 17.1 不同资料能做什么

| 用户拿到的资料 | 可开展的工作 | 需要明确的限制 |
|---|---|---|
| 同一文物的多视角实拍RGB，含相机或可估计相机 | 稀疏重建、真实留出视角对比、过程图、漫游 | 训练与测试图分离；核对掩膜、静态性、曝光和位姿 |
| 实拍视频 | 合理抽帧后作为多视角输入候选 | 相邻帧可能重复且存在模糊、压缩、动态曝光；帧数不等于视角覆盖 |
| 公开纹理三维模型，如OBJ／GLB／glTF | 固定相机与光照渲染多视角，构建受控合成实验 | 写成文物模型衍生的合成视图，不称为真实实拍重建 |
| 只有单张图片或不相关图片 | 可展示资料，不能直接用于本章稀疏多视图协议 | 单图重建需要另一套方法和假设 |
| 已有3DGS PLY但没有训练图／相机 | 可渲染展示已有资产 | 无法据此声称本文从稀疏输入完成重建，也难以进行公平新视角评测 |

### 17.2 首批对象建议

先选择2—3个对象形成互补特点，如表面纹理清楚的雕塑、带细部雕刻／孔洞的器物、轮廓较规整的陶器。首批优先静态、不透明、反光较弱、背景可分离、具有充分环绕视角的对象。

大面积镜面铜器、透明玉石／玻璃、强反光与严重遮挡可作为后续困难案例。大型遗址、建筑立面与单体文物的掩膜和视角覆盖条件不同，不默认直接套用同一Visual Hull设置。

实拍图像数量没有统一硬性门槛。规划上可先检查是否有数十张清晰、非重复的多视角照片及足够独立测试视角；最终按覆盖情况、位姿可用性与显存确定。训练输入仍固定4／6／9视图，不把其余照片自动用于几何／修复监督。

### 17.3 数据接入检查

- [ ] 对象名称、收藏／来源机构、数据页面、对象ID、下载版本、资产许可和论文署名方式已登记。
- [ ] 多张图片确属同一静态对象，视角覆盖和分辨率可用。
- [ ] 相机内外参可用，或已声明辅助标定协议；坐标、尺度、畸变与图像尺寸一致。
- [ ] 前景掩膜和背景处理一致；裁剪后正确调整相机内参。
