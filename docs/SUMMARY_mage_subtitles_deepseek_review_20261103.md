## 2. 方法名称和数据范围

- **Mage-Codec无字幕**：原Codec视觉后端，作为原模型参照。
- **Mage-Frames32无字幕**：固定32帧、150000/3136像素、原问题与选项、贪心生成，作为各增强的主要控制。
- **原对齐字幕v1**：只取32个实际采样时刻命中的cue，按时间排序、cue ID去重后拼接。它不是“截取全文前2048 token”；开发集最高752字幕token，没有触及2048上限。未命中其他SRT段是采样规则带来的覆盖缺失。
- **连续字幕v1**：每个原命中cue最多补前后各一个非空cue，间隔至多2秒；合并连续块并加入时间标记，统一2048文本token预算。保留原命中句，超预算时均匀省略完整邻句，记录省略项。
- **DeepSeek独立首答**：真实32帧序列＋同一连续字幕上下文，在不知道Mage候选的情况下回答四选一或拒答。
- **Mage＋DeepSeek复核**：以**无字幕Frames32**为默认，复核通过才采用API独立候选；必要时增加局部密集帧。当前代码并非在连续字幕Mage最终答案上继续叠加裁判。

下列表格都要连同样本范围阅读。dev180、val90、pilot40与short219不能混作同一测试集；pilot40是从dev180按预测冲突及固定一致题抽取的子集，短smoke6来自历史short池，API smoke3包含在pilot40内，不能相加充当新样本。

## 4. 2048预算的实际影响

这是工程预算，不是Mage硬上限，也没有证明最优。连续字幕dev180中8视频／24题省略邻句；完整邻句文本需要2080—2649 token，3072可容纳本次全部邻句。但**3072推理没有跑过**，不能写成已验证收益或据此归因。

预算受限24题：无字幕18、原对齐18、连续19；其他156题分别92、99、100。没有同配置的不限预算对照，无法确定预算造成多少实际损失。局部邻句扩展也无法覆盖长视频中远离32个采样点的重要内容。

第595／596题所在视频**没有因2048预算省略邻句**，关键事实仍没有被送入API；这说明该案例的主要缺口是证据选择范围，单纯扩大2048不能自动补进这些远处字幕。

## 5. 长20题为什么全部回退

原始单元重算的流程分解：

- 6题：API有效答案与无字幕Mage相同，无需覆盖。
- 9题：正常返回证据不足，回退。
- 1题：第579题引用数量校验失败，回退；暂不修复。
- 1题：第674题动作识别，首答不同但未给合法密集窗口，未进入复核，回退。
- 3题：实际进入第二轮复核，第595、596、710题均返回证据不足，回退。

因此长20题覆盖数0，救回0、误伤0，8/20与默认基线逐题相同。其差值区间[0,0]只是这些题输出完全相同的计算结果，不代表未知数据风险为零或已证明统计等效。

### 5.1 第595题：选举承诺没有取到

问题是戴眼镜的人为什么当选俱乐部主席。Mage为D，原对齐、连续字幕和API首答为正确C；API首答自己标`complete=false`。

第二轮现有输入只能看到清偿债务、商业运作等旁证，没有完整承诺，因此拒绝确认。该片长约2172秒，32张全局帧最大间隔约70秒；Object Reasoning不触发新增密集序列，第二轮主要是相同图文重审。

原SRT cue51—61、约02:28—02:54，包含“竞选成功将引入菲戈，否则承担季票费用”，随后交代选举获胜。这些具体句子不在当前输入中。它们支持优先测试按缺失事实检索连续原字幕，而不是反复让模型对旁证提高信心。此处只是诊断，不算新模型实验成果。

### 5.2 第596题：防守型中场的直接解释没有取到

Mage、原对齐及连续字幕均为C，API首答为正确D，但同样标`complete=false`。当前输入提到防线缺口、优先购买进攻球星，没有明确说明防守型中场；复核拒绝将泛化解释当作充分证据。

原SRT cue748—751、约27:33—27:44，直接说明阵容不平衡与缺少真正防守型中场。这些句子没有进入输入。该题更有价值的潜在改进是主动找回这个事实，并检验找回后能否正确覆盖；不能因已知GT直接把这段塞入实验。

### 5.3 第710题：拒绝错误候选是正确保护

原Mage为正确C，API首答D。题目要求6种赠品的完整出现顺序；补看的两个8秒窗口只支持部分列表，无法确认眼镜与鞋的相对位置。复核拒绝覆盖，保留C，避免了一次误伤。

这个案例说明不能笼统放松“完整性”要求，也不能把所有拒绝都视为过度保守。需要让系统针对缺失的两个物品主动查看对应位置。

### 5.4 额外的程序性保守：第325题

这是中等视频，不是长视频。首答和复核都为正确C，均标充分/完整；已提供密集帧，但模型只引用原全局帧ID，未引用新增密集帧ID，因此固定规则拒绝覆盖。代码将“发生在视频前/中/后”的粗时间定位与全片计数归为相同密集引用要求，存在需要讨论的过度保守之处。

本次仅记录，不改变该题结果。后续若调整，应定义普遍适用、与GT无关的任务证据要求，并保留旧判决作对照，不能专门为这题放宽。

## 7. 关于“Agent、多轮验证、只有确信才纠正”

### 7.1 可以讨论，但把“确信”定义为证据条件

身份提示“你是严谨裁判”、自报90%概率、同一模型重复两遍一致，都不等于正确。当前第438／440题已经出现复核自报充分而仍答错；不能只增加一句“必须确信”就认为误伤得到控制。

推理任务研究发现，无外部反馈的自我纠错有时会退化；CRITIC则强调借助工具反馈修正。它们是设计依据，并非对DeepSeek视频问答的涨点保证：[Self-Correction研究](https://arxiv.org/abs/2310.01798)、[CRITIC](https://arxiv.org/abs/2305.11738)。

### 7.2 最小可讨论路线：有预算的主动补证据循环

1. **列出缺口，而不只输出confidence。** 记录问题约束：人物、时间/阶段、关系、计数、顺序、否定范围；逐项给出已支持、未知或矛盾。缺什么事实、需要何种观察由模型提出，程序核对范围，不读取GT。
2. **让工具取得新证据。** 对文本因果题，从当前视频完整SRT检索相关连续片段，保留cue ID与时间；对视觉题，定位后重新解码真实局部帧，必要时放大。不能用模型自产描述替代画面，也不借外部百科回答原视频问题。
3. **证据补取不只限于任务名为动作/计数。** Object Reasoning也可请求看新片段；第595／596题不应因任务类别而只能原地重审。优先文本工具可节省图片费用。
4. **反向核查候选。** 第二轮先就新证据提取可观察事实或独立作答，再检查哪个选项满足全部条件、是否存在反证；允许合理语义推断，不把所有问题都变成逐字匹配，但不得用常识补造视频事实。
5. **明确停止。** 讨论起点为最多2次追加取证；每轮必须有新的cue/真实帧或不同必要视角，没有新增证据就停止。给单题token、帧数、请求数总额；最终仍不足则回退。不得反复提问直到模型同意。
6. **不同问题采用不同覆盖要求。** 粗略前/中/后定位、局部属性、全片计数、全片不存在某事件，所需覆盖范围不同。全片计数或否定题不能凭两个局部窗口就宣布完成。

此方向与[Active Video Perception](https://arxiv.org/abs/2512.05774)的规划—观察—反思循环相近；[官方代码](https://github.com/SalesforceAIResearch/ActiveVideoPerception)当前以Gemini后端为例，不能直接当作DeepSeek可运行插件。本轮只检索参考，没有克隆、安装或执行该仓库。

### 7.3 应怎样验证，而不是怎样保证涨点

- 若后续继续，主要对照应包含“连续字幕Mage”与“连续字幕Mage＋主动取证复核”，同时保留无字幕Mage和当前静态API复核。否则仍可能仅超过较弱默认基线。
- 新方案会访问全文SRT或更多真实帧，属于新信息预算协议，不能与标准原对齐字幕混称同一配置；需要同样信息访问范围的简单取证对照。
- 先离线审计现有20长题的取证失败原因，冻结一套普遍规则，再在原pilot全部40题运行新对照；不能只挑595／596两道已知可救回题。比较真实救回/误伤、拒答和覆盖率、API成本；pilot仍只是开发数据。
- 引用校验问题后续另行修复并用缓存重审，保留旧报告和新版本来源；它解决格式误判，不会自动补齐视频证据。未知测试集收益仍需最终固定方案后检验。
