## 1. 已确认的范围

- 独立的通用视频Demo，不按文旅场景设计，也不与论文评测/3DGS流程绑定。
- 前端React＋TypeScript＋Vite；后端FastAPI＋Python3.11；独立uv虚拟环境。
- 用户上传完整录制视频；后端逐段生成简短解说；网页逐步显示文字并通过浏览器SpeechSynthesis播报。
- 本地Mage-VL推理，复用已有权重，不下载模型、不调用外部LLM接口。
- 第一版只做文字提问；不引入ASR、本地TTS模型、外部TTS服务或事件门控。
- 按片段处理不等于现场实时系统。完整视频已上传，允许预处理一个后续片段，但按片段时间播放解说。
- 支持分阶段检查与重跑。原视频、重要历史结果和权重保留；无用代码和重复派生缓存待迁移验收后清理。

## 6. S1：最小React＋FastAPI＋本地Mage链路

1. 实现React页面：上传、播放器、状态区域、文字提问和流式回答。
2. 实现FastAPI健康检查、视频上传、视频读取/拖动播放和问题SSE接口。
3. 只从`Project/models/mage-vl`加载，模型和处理器均`local_files_only=True`；启用HF离线变量，无网络回退分支。
4. 首次只运行一个短视频/单图的真实本地推理，Frames＋SDPA；确认中文输出、错误传播和实际显存，再接视频窗口。
5. 单个模型工作进程＋串行GPU队列，禁止多个uvicorn worker各自加载一份模型；开发热重载不包住模型进程。
6. 迁移旧网页/QA服务中的可用逻辑，整理到Project自己的模块，不把旧目录追加到sys.path作为永久依赖。

验收：React上传的视频可以播放和拖动；本地Mage输出通过SSE逐步显示；断开请求/模型报错能终止并返回明确状态，不让streamer永久等待。

## 7. S2：自动分段解说、任务持久化与Codec接入

1. 对完整录制视频按初始8秒一段建立任务清单；逐段处理，不先把全视频片段Tensor搬进显存。
2. 每段生成简短中文解说，保存原始生成、片段时间、配置身份、完成状态；失败片段可以续跑。
3. 预取最多一个后续片段，前端按原视频时间呈现，队列有界。
4. 接入Codec时先检查`codec-video-prep`与本地工具，再比较同视频Frames/Codec接口是否正确；不把新安装二进制未经检查当作已可用。
5. 原视频只上传保存一次；不永久保存每帧JPEG；临时片段、Codec缓存与用户原视频分目录。
6. 用户提问优先于尚未开始的自动解说；已经运行的生成通过可验证的停止机制取消，不强杀整个后端。

验收：短视频可连续产生多段解说；停止后续跑不会重做已完成且身份一致的片段；队列不会无限积压；日志能定位失败阶段。

## 8. S3：浏览器TTS队列与播放同步

1. 浏览器调用SpeechSynthesis，首次点击“开始讲解/开启播报”后启动，满足用户手势要求。
2. 按完整短句入队，不逐个token创建语音。文本先显示、语音依次播放。
3. 识别当前可用中文音色，处理`voiceschanged`；可优先使用标记为localService的本机音色。浏览器/系统是否使用网络音色不能由后端保证。
4. 一次只播一句，限制排队数量；语音时长过长时控制解说长度或暂停等待，不任由音频越积越多。
5. 暂停、恢复、停止、拖动、切换视频分别处理。跳转或新提问时递增会话版本号，取消旧播报并丢弃过期事件。
6. 浏览器不支持或没有中文音色时，仍保留文字解说并提示当前状态，不自动改用付费服务。

验收：文字流式显示时能够开始播报首个完整句子；跳转后不读旧片段；暂停/恢复在目标浏览器上实测；未接入ASR或外部TTS。
