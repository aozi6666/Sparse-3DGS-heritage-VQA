# 固定 K=20 的视频内字幕检索

目标是测量 2048 个字幕 token 能保住多少 C 组正确题。C 指固定 K=20 融合后重新按时间对齐并加邻句的现有方案。CPU 审计逐题重建 C，要求与冻结记录逐字相同。使用本地 Mage tokenizer 计算含时间戳的字幕 token。视觉和问答提示沿用 B/C。

* TVQA 本地 dfb0e5f 的 preprocessing.py:get_located_sub_text 按标注起止时间取字幕，空窗口取最近邻；tvqa_dataset.py 使用 located_sub_text。此处使用最终画布对应时间，无人工时间标注。
* 本地 VRAG 为 Alibaba-NLP/VRAG，3cc25fb。search_engine/search_engine.py 为嵌入模型与 FAISS 索引，和视频问答的同名 CVPRW 论文应分别引用。本实验独立实现词项检索，无新增模型或索引文件。
* C 有命中且在上限内时，两组逐字沿用 C。对于超预算题，将 C 中连续字幕分为至多三句、相邻间隔至多 2 秒的短段，按时间序列递归取中点，以覆盖前中后段。Time 按这个顺序填至 2048。Hybrid 先用同一顺序填至 1536，再按 BM25 从全片同样划分的短段中取完全在 C 之外且正分的段，剩余预算继续按时间填充。分词小写、去常用停用词，仅使用题干。BM25 的 k1=1.2、b=0.75。每次以完整短段试放，连续四次超额结束该轮。入选 cue 去重、按原时间顺序合并相邻片段。上限相同，实际 token 允许不同。
* 有 SRT 但 C 为空时，Hybrid 尝试全片 BM25。缺失或空字幕保持空。检索可能错过同义表达或引入干扰对白。实验前固定参数。
* bash run_cpu.sh 低优先级单进程，可重入。results 下逐题压缩保存两组文本、cue ID、C 引用、来源与视觉摘要及实际 token；summary.json 为 CPU 审计。CPU 不启动问答。
* B/C 完成后单独运行 bash run_qa.sh。每题每组写入独立 SQLite 检查点，确定性输入相同时复用已有答案。qa 子目录汇总相对 C 和同预算时间组的改对／改错，以及旧字幕独有、视觉独有子集。输入使用同一批 714 题，结果属于该子集。
